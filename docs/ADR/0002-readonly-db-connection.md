# ADR-0002: اتصال قاعدة البيانات للقراءة فقط (read-only) كحماية شرعية

- Date: 2026-05-12
- Status: Accepted

## Context
`quran.db` مرجع علمي ديني مراجَع ومعتمد من مركز تفسير: نص القرآن، خمسة تفاسير،
تحليل لغوي لـ77,432 كلمة، أسباب نزول، قراءات. أي تعديل عرضي على هذا المحتوى —
ولو خطأً برمجيًّا (UPDATE/DELETE غير مقصود) — هو إخلال شرعي فادح. الأدوات تُجري
استعلامات قراءة فقط بطبيعتها، لكن الاعتماد على «النية» وحدها غير كافٍ؛ يلزم ضمان تقني
يجعل الكتابة **مستحيلة** على مستوى الاتصال نفسه.

## Decision
كل اتصال بقاعدة البيانات يُفتح بوضعين متلازمين في `src/tafsir/db.py`:
```python
conn = sqlite3.connect(f"file:{path}?mode=ro", uri=True, check_same_thread=False)
conn.execute("PRAGMA query_only = ON")
```
`mode=ro` (URI) يمنع الفتح للكتابة على مستوى نظام الملفات؛ و`PRAGMA query_only=ON`
طبقة دفاع ثانية ترفض أي عبارة كتابة. كل SQL معاملي (`?` placeholders) حصرًا — لا f-strings.
هذه الطبقة ضمن منطقة «لا تلمس».

## Consequences
- ✅ استحالة تعديل المحتوى الديني خطأً من داخل التطبيق.
- ✅ دفاع بطبقتين (URI mode + PRAGMA) — أيّهما كافٍ، واجتماعهما أمتن.
- ✅ يتّسق مع `openWorldHint=False` وكون الأدوات كلها قراءة.
- ⚠️ بناء الفهارس/FTS يتطلّب اتصالًا منفصلًا read-write (`scripts/build_fts.py`)،
  يُشغَّل يدويًّا خارج مسار التطبيق، لا من داخل أداة.
- ⚠️ لا تهيئة schema وقت التشغيل — الـDB تُبنى مسبقًا وتُخبز في الصورة.

## Alternatives Rejected
- **اتصال عادي (read-write) مع الاعتماد على عدم كتابة الكود:** هشّ، يكفيه خطأ واحد لكارثة.
- **صلاحيات نظام الملفات فقط (chmod):** لا تحمي داخل العملية، وتختلف عبر البيئات/الحاويات.
- **`PRAGMA query_only` وحده دون `mode=ro`:** يمكن إبطاله بـPRAGMA معاكس؛ الطبقتان أأمن.
